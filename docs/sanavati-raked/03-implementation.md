# پیاده‌سازی ماژول «اقلام سنواتی و راکد»

## محل کد (همه داخل `audit-google-auto.html`)
| بخش | نشانگر | توضیح |
|---|---|---|
| موتور محاسباتی | `<<<SR-ENGINE-BEGIN>>>` … `<<<SR-ENGINE-END>>>` | تاریخ شمسی، خواندن مبلغ (عدد صحیح بزرگ)، ساخت رویدادها، لایه‌ها، کران حداقل/حداکثر، فعالیت، سال بعد. بدون وابستگی به صفحه. |
| رابط کاربری | `<<<SR-UI-BEGIN>>>` … `<<<SR-UI-END>>>` | ماژول سوم با ۶ مرحله. فقط نمایش و دریافت تصمیم حسابرس؛ هیچ عددی اینجا ساخته نمی‌شود. |
| اتصال به برنامه | `stepReady`، `gotoModule`، `gotoStep`، `renderStepper`، صفحهٔ اول، دروازهٔ افتتاحیهٔ مشترک | فقط یک شاخهٔ `sr` اضافه شده؛ رفتار دو ماژول قبلی تغییری نکرده است. |

## مراحل
1. فایل‌های سال‌ها (هر سال یک فایل؛ انتخاب سال رسیدگی؛ امکان افزودن فایل اصلی).
2. ستون‌ها، ستون‌های کلید طرف حساب و تاریخ شروع/پایان سال مالی برای هر فایل.
3. تأیید سند افتتاحیه و اختتامیهٔ هر سال (پیشنهاد برنامه + اصلاح دستی).
4. برچسب حساب‌ها (بانک/صندوق، اسناد دریافتنی/پرداختنی، اشخاص) و انتخاب حساب‌های مورد رسیدگی؛ تأیید تطبیق کدینگ بین سال‌ها.
5. آستانه‌ها و روش تاریخ مرز؛ تأیید اتصال برگشت چک/برگشت سند؛ اصلاح برچسب رویدادها.
6. گزارش‌ها: سنواتی، راکد (هر آستانه)، استثناها، پیگیری سال بعد، نمای ریز حساب، راهنما؛ چاپ و خروجی اکسل.

## خواندن فایل
ماژول مقدار خام سلول را می‌خواند (نه متن قالب‌بندی‌شده) تا تاریخ‌های اکسلی قرن خود را از دست ندهند و مبلغ‌ها گرد نشوند.

## آزمون‌ها
- `node tests/sanavati-raked/run.js` — ۳۵ آزمون موتور (موتور مستقیماً از فایل HTML استخراج می‌شود). شامل:
  - همهٔ مثال‌های متن مرجع (بند ۹، ۱۲، ۱۳، ۱۴، ۴، ۱۵) و ایرادهای بخش «الف» بازبینی؛
  - آزمون ویژگی‌محور: کران‌های موتور با جست‌وجوی کامل همهٔ تخصیص‌ها و ترتیب‌های درون‌روز مقایسه می‌شود (برابری دقیق)؛
  - تزریق پیش‌پرداخت پنهان؛ ثابت ماندن اثرانگشت سال رسیدگی با افزودن فایل سال بعد.
- `npm i --no-save jsdom@24 && node tests/sanavati-raked/e2e-browser.js` — آزمون سرتاسری ۶ مرحله در مرورگر شبیه‌سازی‌شده.
