# ماژول «اقلام سنواتی و راکد» — طرح فنی، جدول تصمیم، شبه‌کد و فهرست آزمون‌ها

> وضعیت: **منتظر تأیید کاربر** (بند ۲۱-۱۰ مستند). کدنویسی پس از تأیید شروع می‌شود.
> پیش‌نیاز: `01-logic-review.md` (ایرادهای مستند و تصمیم‌های گرفته‌شده).

تصمیم‌های کاربر که این طرح بر آن بنا شده:
- اسناد **چند سال**، **هر سال یک فایل اکسل جدا**.
- سال مالی ممکن است **غیرتقویمی** باشد ← تاریخ شروع/پایان هر فایل را کاربر تأیید می‌کند.
- ستون‌های کلید طرف حساب را کاربر **برای هر فایل** انتخاب می‌کند.
- گروه حساب‌ها (بانک، صندوق، اسناد دریافتنی/پرداختنی، اشخاص): **پیشنهاد خودکار + برچسب دستی**.
- شمارهٔ چک/فاکتور فقط **داخل شرح** است ← اتصال‌ها فقط پیشنهادی و نیازمند تأیید.
- تاریخ مرز: تنظیم قابل تغییر؛ پیش‌فرض «ماه تقویمی شمسی، روز مرز = قدیمی».

## ۳. مدل داده

```text
Event   { eid, fileYear, docNo, rowNo, srcRow, day, key, side:'D'|'C', amount:BigInt,
          docType:'OPENING'|'CLOSING'|'NORMAL', tags:Set, tagStatus:'auto'|'confirmed',
          link:{pairEid, status:'suggested'|'confirmed'}|null, descDoc, descRow }
          // ردیفی که هم بدهکار و هم بستانکار دارد → دو رویداد جدا (گردش ناخالص حفظ می‌شود)
Layer   { lid, side, size:BigInt, bornEarly:day|UNKNOWN, bornLate:day,
          origin:'KNOWN'|'PRE_PERIOD'|'GAP'|'SUSPECT'|'TRANSFER', srcEid }
Consumption { eid, lid, amount, pass:'MIN'|'MAX' }
KeyState { key, pass, layers:Layer[], log:Consumption[] }
Snapshot { auditYear, perKey: {MIN:KeyState, MAX:KeyState, book:{amount, side}}, digest }
```

**ثابت UNKNOWN** = کوچک‌تر از هر تاریخی (منفی بی‌نهایت). در گزارش «قبل از دورهٔ اطلاعاتی / قدمت نامشخص» نمایش داده می‌شود.

**بازهٔ تولد لایه** (اصلاح ایراد ۳ بازبینی):

| منشأ لایه | bornEarly | bornLate |
|---|---|---|
| افزایش عادی | روز رویداد | روز رویداد |
| افتتاحیهٔ اولین سالِ موجود برای کلید | UNKNOWN | روز قبل از شروع آن سال |
| افتتاحیهٔ پس از سال مفقود / زنجیرهٔ قطع‌شده | UNKNOWN | روز قبل از شروع آن سال |
| مازاد افتتاحیه نسبت به اختتامیهٔ سال قبل | UNKNOWN | روز قبل از شروع سال |
| افزایشِ با برچسب انتقال/تجدید طبقه‌بندی (حتی پیشنهادی) | UNKNOWN | روز رویداد |
| برگشت چکِ بدون اتصال تأییدشده | UNKNOWN | روز رویداد |
| بخشِ عبورکرده از صفر (لایهٔ خلاف‌جهت) | روز رویداد | روز رویداد |

نکتهٔ کلیدی: بازه فقط روی پیمایش **بیشینه** اثر دارد (چون پیمایش کمینه از `bornLate` استفاده می‌کند که همان روز رویداد است). پس برچسب‌های **پیشنهادیِ تأییدنشده** را می‌توان بدون خطر به کار برد: فقط بیشینه را محتاطانه بزرگ‌تر می‌کنند و کمینه را دست نمی‌زنند. در مقابل، **حذف جفت متصل** (برگشت چک/برگشت سند) روی کمینه اثر دارد و فقط با **تأیید** انجام می‌شود.

## ۴. جدول تصمیم کامل (اثر هر رویداد)

| رویداد | مانده دفتر | لایه‌ها | ساعت فعالیت | منبع عدم‌قطعیت / استثنا |
|---|---|---|---|---|
| OPENING، اولین سال کلید | = جمع افتتاحیه‌های کلید (تجمیع، نه جایگزینی) | یک لایه PRE_PERIOD | — | «قبل از دوره» (مبلغ) |
| OPENING، سال بعدی، برابر با مانده پیش از اختتامیهٔ سال قبل (مبلغ و سمت) | همان | لایه‌های سال قبل حمل می‌شوند | — | — |
| OPENING، اختلاف با سال قبل | = افتتاحیهٔ دفتر | حمل لایه‌ها + مازاد: لایهٔ SUSPECT / کسری: کاهش با قاعدهٔ هر پیمایش | — | استثنا: «افتتاحیه/اختتامیه نامنطبق» + مبلغ اختلاف |
| OPENING پس از سال مفقود | = افتتاحیه | اگر صفر: هیچ (پل صفر)؛ وگرنه یک لایه GAP | — | استثنا: «سال مفقود» (اگر غیرصفر) |
| CLOSING | از مانده پایان کنار گذاشته می‌شود | — | — | کنترل: قرینهٔ مانده پیش از اختتامیه باشد، وگرنه استثنا |
| افزایش عادی | + | لایهٔ جدید | — | — |
| کاهش عادی / UNKNOWN | − | پیمایش کمینه: قدیمی‌ترین اول؛ بیشینه: جدیدترین اول | پیش نمی‌رود | «کاهش بدون شاهد تخصیص» (مبلغ) |
| کاهش بیش از مانده | − و تغییر سمت | مصرف همه + لایهٔ خلاف‌جهت | — | پرچم «تغییر ماهیت» |
| کاهش + ردیف نقدیِ تأییدشده، سند ساده و متوازن | − | مثل کاهش عادی | FULL | — |
| کاهش + ردیف نقدی، سند مرکب | − | مثل کاهش عادی | POSSIBLE | «سند مرکب مبهم» |
| CHECK_RECEIVED (ردیف مقابل اسناد دریافتنی) | − | مثل کاهش عادی | PROVISIONAL | توضیح سیاست چک در گزارش |
| CHECK_COLLECTED | روی کلید اسناد دریافتنی | — | FULL روی همان کلید | — |
| CHECK_BOUNCED، اتصال تأییدشده | + | جفت حذف و **محاسبه از ابتدا دوباره** | PROVISIONAL آن دریافت → باطل | — |
| CHECK_BOUNCED، بدون اتصال | + | لایه SUSPECT با بازهٔ تولد | — | «برگشت بدون اتصال» (مبلغ) |
| CORRECTION / REVERSAL بدون مرجع | ± | مثل رویداد عادی هم‌جهت | پیش نمی‌رود | «اصلاحیهٔ بدون مرجع» (مبلغ) |
| REVERSAL با اتصال تأییدشده | ± | جفت حذف و محاسبه از ابتدا | — | — |
| TRANSFER/RECLASS واردهٔ بدون مرجع | + | لایه TRANSFER با بازهٔ تولد | پیش نمی‌رود | «انتقال نامشخص» (مبلغ) |
| TRANSFER/RECLASS صادره | − | مثل کاهش عادی | پیش نمی‌رود | — |
| NONCASH_SETTLEMENT تأییدشده | − | مثل کاهش عادی | FULL | — |
| ردیف با تاریخ نامعتبر / بدون کد / مبلغ نامعتبر | **وارد محاسبه نمی‌شود** | — | — | استثنا + **مانده آن کلید «غیرقابل اتکا»** علامت می‌خورد |

ترتیب پردازش: سال ← روز ← (در هر روز و هر کلید) **اول همهٔ افزایش‌ها، بعد همهٔ کاهش‌ها**؛ داخل هر گروه بر اساس شماره سند و ردیف (فقط برای پایداری شناسه‌ها). اگر مانده ابتدای روز صفر است، اول بدهکارها.

## ۵. شبه‌کد اصلاح‌شده

```js
// ---------- E7: دفتر لایه‌ها برای یک کلید و یک پیمایش ----------
function runKey(keyEvents, years, pass, opts) {          // pass: 'MIN' | 'MAX'
  const st = { layers: [], log: [], flags: [], yearEnd: {} };
  let prevYear = null;
  for (const y of years) {                                // سال‌ها به ترتیب تاریخ شروع
    const ev = keyEvents.filter(e => e.fileYear === y.id && !e.voided);   // voided = جفت متصل تأییدشده
    const opening = netOf(ev.filter(e => e.docType === 'OPENING'));       // {amount, side} تجمیع‌شده
    if (!prevYear || !isConsecutive(prevYear, y) || !st.chainOk) {
      st.layers = [];                                     // هر چه قبلاً بوده، دیگر قابل ردیابی نیست
      if (opening.amount > 0n)
        push(st, opening.side, opening.amount, UNKNOWN, y.start - 1,
             prevYear ? 'GAP' : 'PRE_PERIOD');
      if (prevYear && !isConsecutive(prevYear, y)) st.flags.push(gapFlag(opening));
    } else {
      const carried = st.yearEnd[prevYear.id].book;       // مانده پیش از اختتامیهٔ سال قبل
      const diff = signedDiff(opening, carried);          // با رعایت سمت
      if (diff !== 0n) {
        st.flags.push({ code: 'OPENING_MISMATCH', amount: abs(diff) });
        applyAmount(st, diff, y.start - 1, pass, { suspect: true });   // مازاد = لایه SUSPECT، کسری = کاهش
      }
    }
    const normal = ev.filter(e => e.docType === 'NORMAL');
    for (const day of uniqueSortedDays(normal)) {
      const today = normal.filter(e => e.day === day);
      const side0 = sideOf(st) || 'D';                    // سمت مانده در ابتدای روز
      const incs = today.filter(e => e.side === side0);
      const decs = today.filter(e => e.side !== side0);
      for (const e of [...stableSort(incs), ...stableSort(decs)]) applyEvent(st, e, pass);
    }
    st.yearEnd[y.id] = { book: balanceOf(st), layers: deepCopy(st.layers) };
    assertBalanceMatchesBook(st, ev);                     // E11: مبلغ و سمت، جدا
    prevYear = y;
  }
  return st;
}

function applyEvent(st, e, pass) {
  const side = sideOf(st);
  if (!side || side === e.side) {                         // افزایش
    const [early, late, origin] = birthRangeFor(e);       // طبق جدول بند ۳
    return push(st, e.side, e.amount, early, late, origin, e.eid);
  }
  let rest = e.amount;                                    // کاهش
  const order = pass === 'MIN'
    ? [...st.layers].sort((a, b) => a.bornLate - b.bornLate || a.lid - b.lid)     // قدیمی‌ترین اول
    : [...st.layers].sort((a, b) => b.bornEarly - a.bornEarly || b.lid - a.lid);  // جدیدترین اول
  for (const L of order) {
    if (rest === 0n) break;
    const take = min(rest, L.size);
    L.size -= take; rest -= take;
    st.log.push({ eid: e.eid, lid: L.lid, amount: take, pass });
  }
  st.layers = st.layers.filter(L => L.size > 0n);
  if (rest > 0n) {                                        // عبور از صفر: سمت پس از هر رویداد دوباره تعیین می‌شود
    push(st, e.side, rest, e.day, e.day, 'KNOWN', e.eid);
    st.flags.push({ code: 'SIGN_CHANGE', eid: e.eid, amount: rest });
  }
}

// ---------- E8: شاخص‌ها روی Snapshot سال رسیدگی ----------
function olderThan(stateMin, stateMax, cutoffDay, endSide) {
  const lo = sum(stateMin.layers.filter(L => L.side === endSide && L.bornLate  <= cutoffDay));
  const hi = sum(stateMax.layers.filter(L => L.side === endSide && L.bornEarly <= cutoffDay));
  return { min: lo, max: hi };                            // E11: min <= max <= مانده هم‌جهت
}
sanavati   = olderThan(MIN, MAX, audit.start - 1, endSide);
stale[T]   = olderThan(MIN, MAX, cutoff(audit.end, T, opts), endSide);   // برای هر آستانه
byOrigin[Y]= olderThan(MIN, MAX, Y.start - 1, endSide);  // فقط تجمعی: «قدیمی‌تر از شروع سال Y»
unknownPart= { min: sum(MIN pre-period/gap layers), max: sum(MAX layers with bornEarly===UNKNOWN) };
modelFreeMax[c] = min(grossIncreasesOnEndSideUpTo(c) + preperiodOnEndSide, endBalance);
reboundRisk[c]  = modelFreeMax[c] - stale[c].max;        // مبلغ در معرض «پیش‌پرداخت / مصرف قبل از ایجاد»
width = endBalance === 0n ? null : (max - min) / endBalance;   // مخرج صفر ← خالی

// ---------- E9: وضعیت فعالیت (مستقل؛ روی اعداد قدمت اثر ندارد) ----------
function activityOfDecrease(e, doc, tagsOfAccount) {
  if (e.tags.has('CORRECTION') || e.tags.has('REVERSAL') || e.tags.has('TRANSFER') || e.tags.has('RECLASS'))
    return 'NONE';
  if (!doc.balanced) return 'UNKNOWN';
  if (counterRows(doc, e).some(r => tagsOfAccount(r) === 'NOTES' && r.side !== e.side)) return 'PROVISIONAL';
  const C = sumOpp(doc, e, 'CASH');                       // فقط برچسب‌های تأییدشده
  const S = sumSameSideOthers(doc, e);                    // سایر ردیف‌های هم‌سمت (به‌جز همین کلید)
  if (C === 0n) return e.tags.has('NONCASH_SETTLEMENT') && e.tagStatus === 'confirmed' ? 'FULL' : 'NONE';
  if (S === 0n && C >= e.amount) return 'FULL';           // سند ساده؛ ارتباط یکتا
  return 'POSSIBLE';                                       // کران ردیفی: lb=max(0,C−S)، ub=min(d,C)
}
// خروجی برای هر آستانه: آخرین FULL، آخرین PROVISIONAL/POSSIBLE، وضعیت در بازهٔ [مرز+۱، پایان سال]

// ---------- E10: Snapshot و سال بعد ----------
snapshot = deepFreeze(perKeyResults); digest = hash(canonicalJSON(snapshot));
nextYear = runFollowUp(clone(snapshot), nextYearEvents);  // فقط روی کپی
// گزارش: کاهش ناخالص، افزایش ناخالص، باقی‌ماندهٔ مانده پایان سال رسیدگی در پایان سال بعد (کمینه/بیشینه)،
//        اسناد سال بعد با شرح «تعدیلات سنواتی/اصلاح سنوات قبل» → فقط علامت‌گذاری
assert(hash(canonicalJSON(snapshot)) === digest);
```

## ۶. تاریخ مرز (پیش‌فرض قابل تغییر)

- `cutoff(end, T)`: شمارش T ماه تقویمی شمسی به عقب؛ اگر روز در ماه مقصد نباشد ← آخرین روز همان ماه.
  مثال: ۱۴۰۴/۱۲/۲۹ − ۶ = ۱۴۰۴/۰۶/۲۹ ؛ ۱۴۰۴/۰۶/۳۱ − ۶ = ۱۴۰۳/۱۲/۳۰ (۱۴۰۳ کبیسه).
- قدیمی: `تولد ≤ مرز`.
- گزینه‌های جایگزین در تنظیمات: «تعداد روز ثابت» و «تولد < مرز». روش انتخابی در سربرگ گزارش چاپ می‌شود.
- آستانه‌های پیش‌فرض: ۶، ۱۲، ۲۴ ماه (هر سه هم‌زمان نمایش داده می‌شوند).

## ۷. گزارش‌ها

۱. **سنواتی**: کلید و عنوان، مانده پایان و سمت، سنواتی کمینه/بیشینه، بخش قدمت نامشخص، عرض بازه، تفکیک تجمعی سال منشأ، منابع عدم‌قطعیت (مبلغی)، هشدارها.
۲. **راکد**: برای هر آستانه: تاریخ مرز، مبلغ قدیمی‌تر کمینه/بیشینه، بیشینهٔ بدون فرض و مبلغ در معرض، آخرین گردش قطعی، آخرین گردش محتمل، وضعیت فعالیت، هشدارها. برچسب نهایی «راکد قطعی» صادر **نمی‌شود** (بند ۲۰).
۳. **استثناها**: همهٔ موارد بند ۱۶ مستند + «تفصیلی ناهمگن در معین».
۴. **نمای ریز کلید**: لایه‌ها و فهرست مصرف هر دو پیمایش با عنوان «یکی از تخصیص‌های ممکن».
۵. **پیگیری سال بعد**.

درجهٔ اطمینان الف/ب/ج نمایش داده **نمی‌شود**؛ به‌جای آن هشدارهای مشخص.

## ۹. مراحل رابط کاربری (پس از تأیید موتور)

۱. بارگذاری چند فایل؛ برای هر فایل: سال مالی، تاریخ شروع و پایان (پیشنهاد از کمترین/بیشترین تاریخ؛ تأیید کاربر)، نقش (قبل / رسیدگی / بعد).
۲. نگاشت ستون‌ها و ستون‌های کلید برای هر فایل (پیشنهاد خودکار مثل ماژول‌های فعلی).
۳. تأیید اسناد افتتاحیه و اختتامیهٔ هر فایل.
۴. برچسب حساب‌ها (بانک، صندوق، اسناد دریافتنی/پرداختنی، اشخاص) و جدول تطبیق کدینگ بین سال‌ها.
۵. انتخاب حساب‌های مورد رسیدگی و تنظیمات (آستانه‌ها، روش تاریخ مرز).
۶. گزارش‌ها و چاپ.

## ۱۰. تصمیم‌های پیش‌فرضی که در این طرح گرفته شد (همه قابل تغییر)

- بازهٔ سنجش فعالیت برای هر آستانه = از روز بعد از تاریخ مرز تا پایان سال رسیدگی.
- فقط کاهش‌های مانده (دریافت/پرداخت/تسویه) «فعالیت» حساب می‌شوند؛ فاکتور جدید فعالیت تسویه‌ای نیست ولی تاریخ آخرین افزایش هم جدا نمایش داده می‌شود.
- مبلغ منفی در ستون بدهکار/بستانکار: به ستون مقابل منتقل و در گزارش استثنا آورده می‌شود.
- مبلغ غیرصحیح (اعشاری): استثنا؛ گرد نمی‌شود.
- هوش مصنوعی در نسخهٔ اول استفاده نمی‌شود.
